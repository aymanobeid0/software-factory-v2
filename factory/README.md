# مصنع البرمجيات (Software Factory)

مصنع بيطبّق مهارات Matt Pocock، بس كل دور فيه وكيل منفصل، فما في وكيل بيقيّم شغله بنفسه. المصنع ما بيعرف شي عن جهاز معيّن أو لغة معيّنة، وكل إعدادات المشروع بتنحط في ملف واحد.

## الأدوار
| الدور | شو بيعمل | بيكتب بـ | المهارة |
|---|---|---|---|
| المخطِّط (إنت + Claude) | الأسئلة، الـ spec، التذاكر، الإعداد، النسخة الفارغة | ملفات الخطة | grill-with-docs، to-spec، to-tickets |
| كاتب الاختبارات | اختبارات حمراء عند الـ seams المتفق عليها | ملفات الاختبار بس | tdd |
| المنفّذ | تذكرة وحدة بكل تشغيل، ودورة أحمر ← أخضر ورا الثانية | ملفات الكود بس | implement + tdd |
| المُتحقِّق | بيشغّل الفحوص بنفسه | ولا شي | — |
| المراجع | بيراجع حسب الـ spec والمعايير | ولا شي | code-review |

كل دور بيشتغل كعملية منفصلة (Claude Code أو Codex). **الحارس** (`hooks/guard.mjs`) بيمنع أي شي برا صلاحيات الدور. و**الحَكَم** (`factory-checkpoint`) هو الطريقة الوحيدة للمنفّذ يعمل commit، وما بيقبل إلا دورة أحمر ← أخضر حقيقية.

## التثبيت
من ريبو المصنع شغّل `./setup.sh`. بيسألك: **Claude Code ولا Codex؟** و**لكل مشاريعك ولا لمشروع واحد؟**
- **Claude Code:** بيتثبت بـ `~/.claude` أو `<project>/.claude`، والأوامر بتبدأ بـ `/`.
- **Codex:** بيتثبت بـ `~/.agents` أو `<project>/.agents`، والأوامر بتبدأ بـ `$`.

اختيارك بينحفظ بـ `factory/runtime.conf`، و`run-role.sh` بيشغّل الأدوار بنفس الأداة (`claude -p` أو `codex exec`). تعريفات الأدوار موجودة بـ `factory/roles/`. التثبيت داخل مشروع بيشتغل كمان بالكلاود و GitHub، وملف `.gitattributes` بيحافظ على نهايات أسطر LF.

المتطلبات: Claude Code أو Codex CLI، و`node`، و`git`، و`bash` (على Windows بيكفي Git Bash)، وأداة اختبار مشروعك بتطلّع تقرير **JUnit XML**.

## الاستخدام على مشروع جديد
1. ما بتحتاج تكتب أي ملف قبل.
2. شغّل `/factory-plan` (لحاله، أو مع فكرة بسطر واحد). المخطِّط بيسألك شو بدك تبني، وبيستكشف المشروع بنفسه، وبعدين بيسألك عن القرارات المفتوحة. بعدها بيكتب `SPEC.md` (فيه `### Seams` و`### Invariants`) والتذاكر، وبيجهّز **`.factory/config.json`** للغة مشروعك، وبيعمل النسخة الفارغة، وبعدين بيجمّد كل شي.
3. شغّل `/factory`. بيمشي على الترتيب: كاتب الاختبارات ← فحص الأحمر ← كل تذكرة (المنفّذ مع الحَكَم ← المُتحقِّق) ← فحص الأخضر ← المراجع.
4. إذا انقطعت الجلسة، افتح جلسة جديدة وشغّل نفس الأمر، وبيكمل من `.factory/state.json` و`.factory/HANDOFF.md`.

## ملف الإعداد `.factory/config.json`
هذا الملف هو المكان الوحيد اللي فيه شي خاص بلغة المشروع. فيه أمثلة لـ TypeScript وPython وGo بملف `config.example.json`.
- `paths.src` و`paths.tests`: أنماط glob. أي ملف بيطابق `tests` بيُعتبر اختبار، حتى لو كان داخل مجلد الكود، وهذا مهم للغات مثل Go.
- `testFile`: ملف الاختبار لكل تذكرة، باستخدام `{ticket}` أو `{ticket_snake}`.
- `commands`: `test` و`testFile` و`testOne` و`junit` (لازم يكتب JUnit XML على `{out}`) و`typecheck` (أو `null`).
- `env.pathPrepend`: مجلدات بتنضاف لـ PATH، مثل `.venv/Scripts`.

## الملفات
| الملف | الوظيفة |
|---|---|
| `run-role.sh` | بيشغّل دور بـ Claude Code أو Codex حسب `runtime.conf`: بيولّد الحارس، وبيعطي الدور تعليماته وإعداد المشروع ومهاراته |
| `roles/` | تعليمات الأدوار الأربعة |
| `install-matt-commands.sh` | بيثبّت مهارات Matt كأوامر، وبيضيف لمهارات الاستكشاف سؤال "بدك تبعث النتيجة للمصنع؟" |
| `hooks/guard.mjs` | الحارس، وقواعده جاية من إعداد المشروع |
| `checkpoint.mjs` و`bin/factory-checkpoint` | الحَكَم، بيقرأ JUnit XML |
| `lib/config.mjs` و`lib/cli.mjs` | قراءة الإعداد والـ globs والأوامر |
| `lib.sh` | أدوات shell للمنسّق |
| `matt-skills/` | نسخة ثابتة من مهارات Matt (`SOURCE.md` بيحدد من وين) |
| `update-matt-skills.sh` | بيحدّث المهارات لآخر نسخة من GitHub |
